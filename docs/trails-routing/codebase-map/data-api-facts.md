# data-api-facts

## Summary
I checked every source live on 2026-09-24, using curl, GDAL 3.13.2, uv, pyosmium 4.3.1 and overturemaps 1.0.2. Test areas: a 50x50 km box near Stanley, ID (W,S,E,N = -115.25, 43.95, -114.63, 44.40) and a small box inside it (-114.98, 44.20, -114.90, 44.26). The research notes were mostly right, with five important corrections.

(1) LANDFIRE does not need the async LFPS job flow or an email. lfps.usgs.gov publishes anonymous ArcGIS ImageServers for each product, e.g. Landfire_LF2024/LF2024_EVT_CONUS/ImageServer. Their exportImage returns an exact 30 m EPSG:5070 Int16 GeoTIFF for a 50 km box in about 1 s. LANDFIRE's documented GeoServer WCS returns identical pixels.

(2) LF 2025 already exists, but only for the SW and NW GeoAreas. Elsewhere it returns all NoData; the rest of CONUS is scheduled for Nov 2026.

(3) The FBFM40 codes are TL4=184, TL5=185, TL7=187 and SB1–SB4=201–204.

(4) The hydro.nationalmap.gov NHD and NHDPlus HR REST services were unreliable (60–110 s timeouts). 3DHP is fast but has no perennial flag. The dependable streams source is the static NHD HU8 GeoPackage zips on S3, found through the TNM Access API; filter NHDFlowline to fcode 46006 (Perennial).

(5) Overpass works but its policy rules it out for a recurring worker. Automated regular use is limited to about 100 queries and 10 MB per day, and one 50 km fire is 8–22 MB. A Geofabrik state PBF plus pyosmium reproduced the Overpass result exactly (1,994 ways) in 6.4 s.

Trails:
- **USFS.** Take the weekly national FGDB zip: 119 MB, ETag/Last-Modified, and conditional GET returns 304. It holds layer Trans_Trail_NFS_Publish: NAD83, UPPERCASE fields, 86,417 segments, of which 78,156 are TERRA. Of the TERRA segments, 3,289 have NULL geometry and 7 are MultiCurve. The REST MapServer is fine for bbox pulls: 2,000-record pages and exceededTransferLimit.
- **BLM.** The hosted FeatureServer BLM_Natl_GTLF_Public_Managed_Trails/FeatureServer/2 (19,532 features) is the complete set of public "Transportation System - Trail". MapServer layers 2–5 are exact subsets of it and must not be unioned. Not_Assessed_Trails/7 (5,038) is disjoint. The roads layers hold Road and Primitive Road. An ogr2ogr pull of all managed trails takes 20 s over 10 pages.
- **NPS.** NPS_Public_Trails MapServer/0 has 31,491 features. PUBLICDISPLAY and DATAACCESS are already all 'Public Map Display' and 'Unrestricted'. Keep the filter defensively and also drop decommissioned, abandoned, proposed and water/snow/ferry features. A full pull takes 22 s over 16 pages.

GDAL's ESRIJSON driver pages automatically when the URL has no resultOffset and has orderByFields=OBJECTID. I checked this against both MapServer and FeatureServer.

DEM and slope: LF2020_SlpD (whole-degree Int16) and LF2020_Elev share the EVT grid, so they are the simplest. 3DEP exportImage (data as of Aug 24, 2026) is fresher but returns Float32, 11 MB and 5 s per 50 km box, and needs 5070 grid alignment. The two slopes correlate at r=0.97.

## Conventions
- GDAL is used only as a CLI via subprocess, with no Python bindings, even though python3-gdal is apt-installed (worker/responder_worker/geopdf.py:3-4, _run at :40). Keep new raster and vector steps as ogr2ogr, gdalwarp, gdal_translate and gdal_rasterize calls.
- All HTTP goes through http.make_client and http.get (worker/responder_worker/http.py): the shared UA from config.USER_AGENT, a 60 s timeout, 3 tenacity retries on transport errors, 429 and 5xx, 304 returned as-is and 404 raising.
- Politeness budgets live in config.py (MAX_CONCURRENT_*, LISTING_DELAY_S). Upstream federal services should be hit sequentially with small delays. Overpass policy additionally demands a unique UA and a 30 s pause on 429/406.
- Minimal dependencies (owner preference): the worker pyproject has only httpx, lxml, rapidfuzz, boto3, tenacity and pypdf. Each new PyPI dependency (osmium, overturemaps+pyarrow) must be justified. Prefer apt CLI tools already installed (gdal-bin) or one small wheel.
- CI runs on ubuntu-latest with apt gdal-bin (Ubuntu 24.04 means GDAL 3.8.4). My tests used GDAL 3.13.2, so avoid options newer than 3.8.
- Python 3.12 via uv (`uv sync`, `uv run python -m responder_worker.cli <cmd>`). New steps become cli.py subcommands and new workflow jobs that copy the apt-with-retries block.
- Per-fire artifacts on B2 use immutable URLs that must never be rewritten. When inputs change, bump a generation segment (hotspots.py pattern).
- Tests live in worker/tests/test_*.py with fixtures in worker/tests/fixtures. Parsers for the messy attribute domains below (USFS grade/width codes, BLM case variants, NPS free text) should be unit-tested against fixtures, not live services.
- Use the owner's dev API for backfills; the prod fire-api is for live-site traffic only (user memory).
- Normalize case for BLM coded fields (values mix 'Transportation System - Trail' and 'TRANSPORTATION SYSTEM - TRAIL') and trim whitespace for USFS date strings ('01/01-12/31 ' with a trailing space).

## Risks
- UNVERIFIED: the LFPS async job flow end-to-end (turnaround time, the status JSON's outputFile field, zip layout in practice). I did not submit a job because the Email parameter would send the owner's address to USGS without explicit approval. The recommended exportImage and WCS paths avoid the email entirely. If LFPS is ever used, the owner must decide which contact address to send.
- The LANDFIRE ImageServer exportImage path works anonymously with ACAO * and 100000 px limits, but the LFPS guide does not document it as a supported programmatic channel. Rate limits and terms are unknown. Keep the documented GeoServer WCS (edcintl.cr.usgs.gov/geoserver/landfire_wcs/conus_2024/wcs) as fallback: it returned identical pixels, but uncompressed (8.4 MB vs 1.0 MB for EVT) and tagged NoData 32767 instead of -9999.
- LF 2025 is partial. Outside the SW/NW GeoAreas the LF2025 services return all -9999 until Nov 2026. The worker must detect all-NoData and fall back to LF2024 per fire, and record which version it used in the route's provenance label. Also check the EVT CSV version matches the raster version; the LF2024 and LF2025 CSVs both have 1,069 rows.
- Grid alignment: requesting LANDFIRE with bbox corners that are not snapped to the 5070 grid (origin -2362425, 3267405; 30 m) makes the server resample (nearest neighbour), shifting class boundaries by up to half a pixel. Snap outward before requesting, and request 3DEP on the same grid if it is used.
- EVT lifeform and EVC lifeform disagree on about 8.5% of cells in the sample (EVT shrub or tree where EVC reports herb cover). The GET v2 continuous shrub multiplier needs EVC 210-299; decide a rule for these mismatches (e.g. EVT_LF picks the class, EVC gives shrub % only when EVC is in 200-299, otherwise 0%).
- The GET v2 recipe treats 'major water' as impassable. EVT 7292 Open Water and FBFM40 NB8=98 both mark water at 30 m. NHD perennial fcode 46006 excludes 55800 Artificial Paths, which run through lakes and wide rivers, and 46000 'Stream/River' with unspecified category. Decide whether to add 46000 and NHDArea/NHDWaterbody polygons.
- The NHD and NHDPlus HR REST services on hydro.nationalmap.gov were intermittently unusable on 2026-09-24 (42-110 s and timeouts). Do not make the per-fire build depend on them; use the TNM Access API plus S3 HU8 GeoPackages. NHD has been frozen since late 2023 (retired Oct 2023), and 3DHP lacks a permanence field.
- The USFS FGDB has 3,289 TERRA segments with NULL geometry and 7 MultiCurve. FlatGeobuf with a spatial index aborts on NULLs; filter them out and force -nlt MULTILINESTRING. The REST service probably has the same NULLs (not checked).
- USFS attribute domains are dirty. typical_trail_grade mixes bins, legacy 'TGxx - +/-a-b%' codes and a literal 'TRAIL_GRADE' (12,079 rows). Tread widths use 'TWnn - a-b INCHES' codes, and date fields carry trailing spaces. About 12% of miles are CENTERLINE-only, and N/A or null uses need a default of 'unknown, assume walkable'.
- Legal use versus firefighter use: 1,443 TERRA segments have hiker_pedestrian_restricted '01/01-12/31', and some ALLOWED_TERRA_USE codes omit hikers. Firefighters may still use them operationally, so product must decide whether the router ignores legal-use restrictions for crews (only showing them in the popup) or down-weights them.
- The EDW weekly refresh is currently flagged as failing ('network issues'). Check Last-Modified or ETag; if the file is stale it will be served from the previous week. The worker should record the source date and show it in the popup.
- BLM MapServer layers 2-5 are strict subsets of layer 7. Unioning them would double count up to 12,593 features. The hosted FeatureServer layer IDs are not 0 (e.g. Managed Trails = /2, Not Assessed = /7). A 4-field groupBy statistics query on MapServer layer 6 returned a 400 'Unable to complete operation'.
- BLM PLAN_ACCESS_RSTRCT 'ADMIN ONLY' and 'AUTHORIZED/PERMITTED USER ONLY' segments are in the public dataset. Decide whether to display them (fire crews count as admin) and label them clearly.
- Overpass: the first 50 km query returned a 504, and the documented policy for regular automated use (under 100 queries and 10 MB per day, commercial use should self-host) conflicts with 5-30 fires/day at 8-22 MB each. GitHub Actions egress IPs are shared with other heavy users. Do not use Overpass in the cron; at most use it for ad-hoc debugging.
- Geofabrik state files are large (California 1.33 GB; us-west 3.4 GB) and a fire near a state line needs two files. Cache by the dated redirect filename in actions/cache (10 GB repo limit) or pick the smallest containing region via index-v1.json. I measured download speed from a laptop, not a GitHub runner.
- ODbL: a routing graph derived from OSM and published on B2 and in offline packs is a Derivative Database. It needs '© OpenStreetMap contributors' attribution and share-alike availability of the derived database. Overture segments carry the same ODbL-1.0.
- The overturemaps 1.0.2 default STAC mode returned 'No data found' for release 2026-09-23.0, so --no-stac was required, and each download scans remote parquet (about 15 s even for tiny boxes). Overture drops OSM node IDs, merges OSM ways and needs connector splitting. It also pulls in pyarrow, contrary to the minimal-deps preference.
- CI runs GDAL 3.8.4 while I tested on GDAL 3.13.2. ESRIJSON auto-paging is documented for ArcGIS Server 10.3 and later and is long-standing, but I did not run it on 3.8.4. GDAL sends POST when the URL is long; the servers accepted this.
- The 3DEP ImageServer caps requests at 8000x8000 px (fine for 50 km at 30 m, 1,667 px). Server-side 'Slope Degrees' is computed at the requested 30 m resolution, which smooths short cliffs. At 30 m in this area it flags about 40% more cells above 45° than LF2020 SlpD (1.79% vs 1.26%), so the choice changes impassable areas.
