# map-layers

## Summary
Map layers in this app are imperative LayerManager modules ({mount, update, unmount}; frontend/src/map/layerTypes.ts:48-55). They are driven from one hook, useMapLayerSync (frontend/src/map/useMapLayerSync.ts). The hook builds a LayerContext (ctx) from zustand state plus TanStack Query data, mounts every manager in MANAGERS once per maplibre instance (:249-253), and calls every manager's update(map, ctx) whenever the ctx memo changes (:276-279). ctx changes on every playback tick, so update() must be idempotent and cheap: each manager keeps module-level last* values and compares against them.

**Where the map exists.** Since the directory pivot there is no national map. App.tsx mounts MapRoot plus useMapLayerSync only when view.mode === 'fire' (App.tsx:225-258, 291-292). Leaving to the directory destroys the map and unmounts every manager. Switching fires without leaving fire mode (popstate, App.tsx:58-61) keeps the same map, so per-fire layers must reset themselves when corneaId changes (pattern: perimeterLayer.ts:58-64).

**Layer order.** One canonical bottom-to-top list, RD_LAYER_ORDER (zOrder.ts:9-57), decides placement. Entries up to and including 'rd-national-perimeters' form the BELOW_LABELS raster group (zOrder.ts:62-64), which is inserted just under the first basemap symbol layer. Everything after it sits above the basemap labels. Every addLayer passes beforeIdFor(map, id). ensureOrder runs again on every 'styledata' event (MapRoot.tsx:122-124) and after a style swap goes idle (MapRoot.tsx:174).

**Style swaps.** Changing theme or map style calls map.setStyle with a transformStyle that carries every rd- source and layer, and the terrain, into the new style (MapRoot.tsx:145-159). Then an 'idle' handler re-runs applyOverrides, resyncBasemapUnderlay, resyncLabelContrast and resyncRdLabelFonts, followed by ensureOrder.

**Basemaps.**
- Vector styles: Dark Matter, Fiord and Classic dark for the dark theme; Positron, Liberty and Voyager for light (app/config.ts:23-34).
- Satellite and Topo: USGS raster underlays managed by basemapUnderlay.ts, driven by ui.basemap. Satellite hides the vector style's background/fill layers only. Topo hides the entire vector basemap.
- DEFAULT_BASEMAP is 'topo' (config.ts:46).
- Offline boot uses a plain #161313 inline style with no glyphs URL (MapRoot.tsx:48-58).

**Label fonts.** rd- symbol layers must take text-font from rdLabelFont(map): 'Noto Sans Bold' when the glyph host is OpenFreeMap, 'Noto Sans Regular' on CARTO. A style swap re-points those stacks (glyphFonts.ts).

**Tap popups today.** Hotspots, historic perimeters and road incidents register map.on('click' | 'mouseenter' | 'mouseleave', layerId). A WeakSet guards against installing handlers twice, the maplibre Popup is created lazily with closeButton:false, and content goes in with setHTML using escaped strings. Each handler first bails if routeClickClaims(directions) (store.ts:249-251). A separate global click handler in useMapLayerSync (:287-322) drops directions pins:
- An armed draw tool wins.
- While exactly one endpoint is missing, the click fills it, even over features.
- With both endpoints set, it moves B only when queryRenderedFeatures finds nothing on its INTERACTIVE list (:289-292).

**Fire context available to layers.** ctx.view.corneaId, ctx.catalog (layers call catalog.fires.find themselves; there is no catalogFire in ctx), ctx.selectedFire, ctx.selectedFireSlug, ctx.perimeterFeature (the version for the scrub time), ctx.spreadRun (its bbox is back-filled after decode), ctx.incidentManifest and ctx.directions. No fire bbox exists in the catalog. The existing boxes are ±0.6°/±0.5° around the catalog coordinates (useMapLayerSync.ts:40-45, 166-169) and the hotspot query box (useFireHotspots.ts:44-65).

**B2 data.** It is reached through dataUrl(rootRelative) (api/catalogs.ts:58-60). Tile sources are declared from catalog-supplied root-relative templates. The pattern is the incident-map raster: tiles:[dataUrl(url_template)], tileSize 256, min/maxzoom and bounds from the manifest, and the source is recreated when the key changes (incidentMapLayer.ts:55-69). The spread forecast is a GeoTIFF decoded client-side into a canvas source corner-pinned from UTM (spreadForecastLayer.ts:140-188; spread/toaRenderer.ts decodeSpreadTiff). productRenderer.ts already has buildLut(stops, discrete) and paintProduct for colouring Uint8 class rasters, which is exactly what a vegetation-class grid needs.

**Toggle UI and URL.** Layer toggles live in ForecastTab's MapLayerToggles (panels/tabs/ForecastTab.tsx:326-373); that tab is labelled 'Layers' in FirePanel. LegendBar shows only spread and weather legends. Toggles are zustand actions on the layers slice that call track('layer_toggled'). Shareable state goes into the query string through app/urlState.ts, and only non-default values are written.

**Offline.** Offline packs are served by a window.fetch wrapper (offline/packs.ts:125-167). That works for raster tiles, which are fetched on the main thread. MapLibre fetches VECTOR tiles inside its web worker with the worker's own fetch (maplibre-gl src/util/ajax.ts makeRequest; vector_tile_worker_source.ts:87), so a vector trails source will bypass the pack unless it goes through maplibregl.addProtocol or per-fire GeoJSON setData.

**Tests.** vitest in the node environment, src/**/*.test.ts only, colocated with sources. They cover pure expression builders, fake-map order checks, pack URL planning and store slices, and render no DOM or React.

**Recommended slots.**
- 'rd-vegetation' (raster) at the very bottom of RD_LAYER_ORDER, under 'rd-traffic'.
- Trail casing and core lines at the top of the below-labels group, immediately before the 'rd-national-perimeters' sentinel. They then sit over the sheets, forecast and weather but under basemap labels.
- A trail-name symbol layer and an invisible wide hit layer at the bottom of the above-labels group, before 'rd-wind-arrows'.
- Route-leg layers extend the rd-route-* tail.

## Conventions
- Every source and layer id we own starts with 'rd-'. Layer ids must be listed in RD_LAYER_ORDER, whose RdLayerId type is what beforeIdFor requires, and each addLayer passes beforeIdFor(map, id). Casting a missing id `as never` compiles but opts out of ordering.
- LayerManager modules keep module-level state (one live map at a time). mount() resets that state. update() runs on every ctx change, including every playback tick, so it must be idempotent and cheap: diff against last* values and guard with map.getLayer before touching the style. unmount() removes handlers, popups, layers and sources, and must tolerate a dead style (it is called inside try/catch at useMapLayerSync.ts:264-270).
- Toggles hide layers with layout 'visibility' and never remove them. Layers are created hidden with layout {visibility:'none'} in mount (historicPerimetersLayer.ts:97, trafficLayer.ts:35). Hot paths avoid setFilter because it regenerates buckets (hotspotLayer.ts header :4-13).
- Server data lives only in TanStack Query; zustand holds UI and client state only (store.ts:1-5, queries.ts:1). Optional layers use lazy queries: enabled only when view.mode==='fire' and the layer is visible (useMapLayerSync.ts:159-172; queries.ts:100-127).
- Self-driven managers that subscribe to the store must bail when the map has died: check `(map as any)._removed || !map.style` (basemapUnderlay.ts:122-123; drawLayer.ts:373-374). They unsubscribe in unmount.
- Popups: a lazily created maplibre Popup with closeButton:false. Content goes in via setHTML with every field escaped through a local esc/escapeHtml helper; ' • ' separators use <span style="opacity:.55">. Cursor becomes 'pointer' on mouseenter. A handlersInstalled WeakSet<MlMap> prevents double registration. Handlers bail when routeClickClaims(directions) is true.
- Colours are TypeScript constants in each layer file, with comments pointing at tokens.css where one exists (perimeterLayer.ts:15). MapLibre paint cannot read CSS variables.
- Store toggle actions call track('layer_toggled', {layer, on}) with free-form event names (app/analytics.ts:60). Per-fire view state resets in selectFire; viewing preferences (basemap, traffic) persist.
- The URL encodes only non-default state, as 1/0 flags or dotted lists. decodeSearch drops unknown values. applyViewState flips a toggle only when needed.
- B2 raster tiles are gdal2tiles 256 px, declared with tileSize 256 (incidentMapLayer.ts:61-64). Dynamic rasters set 'raster-fade-duration':0.
- rd- symbol text uses rdLabelFont(map) so its glyphs follow the active glyph host.
- Tests: vitest, environment 'node', only src/**/*.test.ts (vite.config.ts test block), colocated beside the source. They test pure exported functions (expression builders, codecs, planners) and fake maps. There are no DOM or React component tests and no real maplibre instance.
- File docblocks explain the why, including trade-offs and past bugs, and inline comments explain non-obvious guards. New modules are expected to carry the same header prose.
- The owner wants minimal npm dependencies: prefer MapLibre built-ins (addProtocol, canvas/image sources) and existing geotiff over new packages such as pmtiles.
- Commits and PRs end with the attribution lines from the session system-reminder.

## Risks
- BLOCKER for offline trails: MapLibre fetches vector tiles in its web worker with the worker's fetch (maplibre-gl src/util/ajax.ts makeRequest; vector_tile_worker_source.ts:87), bypassing the OPFS pack wrapper on window.fetch (offline/packs.ts:125-167). A plain {type:'vector', tiles:[https…]} source therefore will NOT render offline even when the tiles are in the pack. Use maplibregl.addProtocol with a custom scheme that calls window.fetch on the main thread (zero dependencies), or ship per-fire trail GeoJSON through setData. The packs.ts:9-11 comment ('MapLibre tile requests go through global fetch') is true only for raster tiles.
- B2 cache rules: 'tiles/' keys are immutable for a year (worker config.py:194), so weekly trail tile rebuilds need versioned key prefixes. The frontend must take the template from a mutable catalog (catalogs/ has max-age=60) and recreate the source when it changes (incidentMapLayer key pattern). Hard-coding a tile URL in the frontend would pin clients to stale tiles.
- Encoding: b2.py sets no ContentEncoding (:135-140) and CONTENT_TYPES lacks .pbf. If the worker writes gzip-compressed MVT (GDAL's MVT driver compresses by default), MapLibre receives gzip bytes and fails to parse. Write uncompressed tiles or add Content-Encoding support.
- Merge conflict and click-arbitration drift: the uncommitted hotspot-flames work in (main checkout) touches zOrder.ts, useMapLayerSync.ts, store.ts and SearchDirectionsControl.tsx, and adds pinDrop.ts FEATURE_LAYERS. That makes three places listing clickable layers (per-layer routeClickClaims guards, INTERACTIVE at useMapLayerSync.ts:289-292, FEATURE_LAYERS). A trails hit layer missing from any of them causes double actions: popup plus moving B, or popup plus a dropped pin. Consider a single exported list.
- This base's ensureOrder moves every rd- layer on every 'styledata' (zOrder.ts:87-105 via MapRoot.tsx:122-124). The uncommitted fix describes this as an endless ~30 fps redraw loop. More layers make each pass costlier, so build on the fixed version.
- Thin trail lines are hard to tap because layer-scoped click tests the exact pixel. A wide invisible hit layer fixes that, but over dense trail networks it will swallow directions B-moves and pin drops when both route ends are set, the same problem noted for hotspots at useMapLayerSync.ts:283-286. The hit width is a UX trade-off.
- Existing popup handlers ignore an armed draw tool, so tapping a feature both places a mark and opens a popup. The new trail handler should also check useStore.getState().draw.tool !== 'none'.
- Basemap-aware styling: ctx has no ui.basemap or theme, and ui changes do not trigger update(). Trail paint that depends on the ground needs a store subscription (basemapUnderlay.ts:121-131) or new ctx fields added to the memo deps; otherwise styles go stale until an unrelated ctx tick.
- Trail legibility: the default ground is USGS Topo (config.ts:46), which already draws its own trails over green woodland tint and brown contours. Our trail style must differ from the USGS dashed black trails. It must also not look like the draw vocabulary (dashed ink fuel break, solid ink hand line with 'H' letters, dotted purple aviation), the dashed road-incident lines, the route blue #4aa3ff, or the new dashed cross-country route legs. A casing plus core pair tuned per ground is advisable: near-black Dark Matter/Classic dark, navy Fiord, pale Positron/Liberty/Voyager, satellite imagery, topo.
- Offline map ground is a plain #161313 background, so offline trail colours must read on near-black. Labels render offline only through MapLibre's local TinySDF fallback, in a system font rather than Noto.
- Vegetation raster CRS: decodeSpreadTiff supports only UTM EPSG:326xx/327xx. LANDFIRE's native CRS is CONUS Albers (EPSG:5070), so the worker must gdalwarp the per-fire grid to the fire's WGS84 UTM zone to reuse the decoder and canvas corner pins; otherwise new reprojection code is needed.
- MapLibre 5.24 has no raster-color, so class colours must be painted client-side (canvas plus buildLut) or pre-coloured by the worker as PNG tiles. Set 'raster-resampling':'nearest' or class edges blend when zoomed in; the spread layer uses the default, linear. A static canvas with animate:true, as spread uses, re-uploads the texture every frame; use animate:false or an image source for vegetation.
- Decode cap: MAX_DECODE_WIDTH 1536 downsamples a large 30 m fire grid for display. Routing needs full resolution, so decode in the routing Web Worker. There are no Web Workers in the app yet; Vite's `new Worker(new URL(...), {type:'module'})` needs no configuration and its chunk lands in /assets, where the service worker precaches it.
- Switching fires can happen without leaving fire mode (popstate re-selects, App.tsx:58-61), reusing the same map and managers. Per-fire trail and vegetation sources, and route legs, must clear on corneaId change (perimeterLayer.ts:58-64 pattern), or the previous fire's grid shows.
- Decide per-fire versus persistent semantics for the trails and vegetation toggles in selectFire (store.ts:358-368). Update urlState.test.ts mkState (:10-26) or buildSearch throws on the missing slices.
- Pack size: sheetTileUrls enumerates the full z/x/y grid. Trail tiles for a generous fire box up to z14-z16 can reach thousands of files, so cap zoom (overzoom beyond the tile maxzoom) and bound the box. Pack failures are all-or-nothing unless the plan entry sets optional:true (packs.ts:347-355).
- Route-leg data shape: the current RouteResult is one LineString used by fitBounds (SearchDirectionsControl.tsx:359-365) and routeLayer. Leg metadata must be added without breaking online engines. The 'all profiles in parallel' flow would also start the offline A* for every A/B change unless gated.
- Perimeter avoidance: ctx.perimeterFeature is the version resolved for the scrub time, not necessarily the latest. SearchDirectionsControl has no perimeter access today, so it needs usePerimeterIndex plus usePerimeterVersion (queries.ts:42-58) to avoid the latest perimeter.
